## 一、顶部 Tab 切换行为

### 1.1 切到 📖 日记 Tab
- **会话：** 新建空 diary 会话（每次都是新的）
- **空状态：** 💬 "这是小麦，你的智能助手..." + 建议问题

### 1.2 切到 🌳 知识 Tab（场景A）
- **会话：** 新建空 wiki 会话（每次都是新的）
- **顶部 select 标题：** 「选知识库…」（placeholder 提示，必须能显示出来）
- **下拉选项列表：** 永远固定顺序：
  1. 🆕 + 创建知识库
  2. （已有 KB 列表）
- **聊天区空状态：** 通用引导 "🌳 我是小麦，已接入 N 个知识库，选一个开始提问，或者创建新知识库" + KB 卡片 + 创建按钮

## 二、知识库下拉选择行为

### 2.1 选已有知识库（如"智能家居知识库"）
- **会话：** 新建空 wiki 会话，kb_id=所选 KB（每次都是新的）
- **顶部 select 标题：** 显示 KB 名（如"智能家居知识库"）
- **聊天区空状态：** 该 KB 专属初始界面 "🌳 我在 xxx 知识库里..." + 建议问题

### 2.2 选 🆕 + 创建知识库
- **会话：** 新建空 wiki 会话 + creatingKb="collecting"（每次都是新的）
- **顶部 select 标题：** 显示「🆕 + 创建知识库」（绝对不能显示"选知识库…"！）
- **聊天区空状态：** 创建知识库专属界面（不是通用 KB 列表）

## 三、创建知识库聊天框（独立受限流程）

### 3.1 定位
**正常聊天，但有边界。** 最终目标只有一个：拿到 KB 名称 + 说明 → 跑一条龙创建。
**不是哑巴机器**，可以回答用户关于创建流程的问题、自我介绍等。

### 3.2 必须拿到的两个信息

| 信息 | 对应字段 | 来源 |
|---|---|---|
| **知识库名称** | `kb.title` | 用户输入的第一部分 |
| **说明/用来干嘛的** | `kb.description` | 用户输入的第二部分 |

### 3.3 用户输入处理规则

| 用户输入类型 | 识别特征 | 我的回应 |
|---|---|---|
| 给了 name + desc（逗号/句号分隔） | 两个信息都有 | ✅ 跑一条龙创建 |
| 只给了 name | 只有一段比较长的 | 引导补 desc："收到！名字叫 xxx 对吧？还差：它是干嘛的？" |
| 问流程/规则 | "怎么创建"/"流程"/"如何"/问号 | ✅ **回答流程**（不是哑巴！）："创建知识库很简单，告诉我名字和用途就行，我帮你连分类都分好～" |
| 自我介绍 | "你是谁"/"你是做什么的" | ✅ 回答："我是小麦，专门帮你创建知识库的..." |
| 否定/质疑 | "不是啊"/"不对"/"你理解错了" | 引导回去："好的！你想创建什么样的知识库？告诉我名字和用途就行～" |
| 聊别的/无关内容 | 其他 | 引导回去："我这边只帮你创建知识库，告诉我名字和用途就行～" |

### 3.4 拿到信息后（一条龙流程）

调用顺序：
1. `wikiOptimizeDescription(kbDesc, kbName)` — AI 优化说明
2. `wikiAddKb(kbName, kbDesc)` — 建 KB
3. `wikiAIDesignCategories(title, description)` — AI 设计分类
4. 循环 `wikiAddCategory(kbId, { name, template_key, sort_order })` — 创建分类
5. 回复用户结果（分类列表 + 每个分类的模板）
6. creatingKb 进入 "done"

### 3.5 创建完成后（done 状态）

- creatingKb = "done"
- 用户再说任何事 → "我这边只帮你创建知识库，已经帮你建好啦 ✅ 去「我的 → 知识库」看详情吧～"

## 四、切换行为总标准（重要！）

### 核心原则

**切 tab / 切 KB / 选创建 / 点 + 新建对话 → 每次都是新空会话**

> 右上角的 "+" 按钮（newChat）和切 KB 效果完全一样：不继承当前 KB，每次都是干净的空会话。

### 场景验证

| 操作 | 结果 |
|---|---|
| 🌳 知识 tab → 选智能家居 KB | ✅ 新空会话（智能家居初始界面） |
| 聊了 3 条 | |
| 切到汽车 KB | ✅ **又一个新空会话**（汽车初始界面） |
| 再切回智能家居 | ✅ **又是一个新空会话** ← 干净！不是之前那 3 条 |
| 聊了 3 条 → 点右上角 **+** | ✅ **又一个新空会话** ← 干净！不继承当前 KB |
| 选 🆕 + 创建知识库 | ✅ **新空会话**（创建初始界面） |
| 聊完创建了 KB | |
| 再选 🆕 + 创建知识库 | ✅ **又一个新的创建初始界面** ← 干净！ |

**历史会话只通过侧边栏历史抽屉访问。** 切 KB/tab 不会自动恢复历史。

## 八、知识 tab 引导汇入流程（v0.2 新增，2026-10-12）

> **核心目标**：把"手动汇入资料进 KB"这个 4-5 步操作，变成"小麦引导 → 用户点一下 → 自动联网查 → 一键汇入"的 1-2 步操作。

### 8.1 现有 handleWikiAsk 机制回顾

```
知识 tab 提问
├── web_search=false（默认）→ ⛔ 严禁 AI 用自身知识，只查 KB 页面
│   └── KB 里没有 → 直接说「知识库里暂时没有这个问题的答案，可以开启联网查询」
│
└── web_search=true → ✅ 允许 AI 用自身知识补充，但要区分来源
    └── 回答里标注：哪些来自 KB（用 [[页面名]]），哪些是 AI 自己补充的
```

### 8.2 触发 import_mode 的 4 个时机（全部透明，用户无感知）

前端发请求前判断，满足任一条件就加 `import_mode=true`：

| # | 时机 | 判定逻辑 |
|---|---|---|
| **1** | **知识 tab 刚进来 + 空 KB + 空 history** | 第一次对话，引导用户第一步怎么建设 KB |
| **2** | **用户自然语言里说"帮我收集/查询 XX 信息"** | question 匹配 `/收集|查询|整理|帮我找|帮我查|帮我搜/` + `/信息|资料|内容/` |
| **3** | **上一条 AI 回答说"KB 还是空的"** | lastAiAnswer 含「还是空的」 |
| **4** | **上一条 AI 回答说"KB 没找到"** | lastAiAnswer 含「暂时没有」 |

**不触发的情况**：用户正常问"知识库里刘备在哪几个事件里出场过？"→ 正常 KB RAG 问答，完全不变。

### 8.3 气泡触发与内容

气泡**不是每个 AI 回答下面都出**（太吵），只在触发 import_mode 的时机里出。

**气泡文案**：

```
🔍 按我知识库的分类和范本，帮我收集 {推荐实体} 的信息
```

- 从这个 KB 的 categories 里取前 2 个分类
- AI 动态推荐实体（和已有 wiki 页面**不重复**）
- 每个气泡有两个按钮：「发送」和「添加到对话」

**示例 1：「三国」KB（分类：人物、事件）**

```
用户刚选了 KB，还没开始对话
→ 出两个气泡：
   🔍 按我知识库的分类和范本，帮我收集 司马懿 的信息  [发送] [添加到对话]
   🔍 按我知识库的分类和范本，帮我收集 夷陵之战 的信息  [发送] [添加到对话]
```

**示例 2：「路亚笔记」KB（分类：装备、钓法、钓点）**

```
用户空 KB，小麦刚说「还是空的～先去添加资料吧」
→ 小麦 AI 回答改成直接出气泡：
   🔍 按我知识库的分类和范本，帮我收集 水滴轮 的信息  [发送] [添加到对话]
   🔍 按我知识库的分类和范本，帮我收集 波爬钓法 的信息  [发送] [添加到对话]
```

**用户点「添加到对话」→ 气泡内容插入输入框 → 用户可以自由修改**（比如加上限定条件：「帮我收集 司马懿 在 239 年之前的主要事迹」）→ 发送 → 后端走 import_mode 特殊流程。

### 8.4 后端 import_mode 特殊流程

```
import_mode=true 的请求进来
│
├─ 1. 强制 web_search=true（不管用户开关）
│     因为用户点气泡 = 他想查 KB 里还没有的东西
│
├─ 2. 拉 KB 的 categories + 每个分类的模板结构
│     wiki_kb_categories 表
│
├─ 3. System Prompt 里注入分类范本参考：
│     「这个 KB 有以下分类和范本：
│      - 【人物】：生平 / 核心事件 / 关系网
│      - 【事件】：起因 / 经过 / 结果 / 影响
│      请自然地组织回答，让内容分布符合这些分类和范本，
│      但语言要流畅连贯，不要生硬分标题。」
│
├─ 4. callLLM → AI 回答
│     （自然语言、连贯，但内容结构上符合范本）
│     ✅ 重点：内容要能直接被汇入！
│
└─ 5. 前端拿到回答 → 底部出现汇入按钮：
      📥 将本次回答汇入「三国」知识库（按【人物】分类）
      （按钮上直接写清楚汇入哪个 KB、哪个分类）

└─ 用户点「是」
      └─ 调 handleWikiIngestAll(kb_id, AI回答文本, category_hint="人物")
         → AI 自动识别实体 → 生成 wiki 页面
         → 补 [[]] 交叉链接 → 完成
```

### 8.5 关键设计决策记录

| 决策 | 结论 | 理由 |
|---|---|---|
| 气泡是否每个 AI 回答下面都出 | ❌ 不是 | 太吵，正常问答不该被打扰 |
| 气泡文案 | 「🔍 按我知识库的分类和范本，帮我收集 XX 的信息」| 让用户一眼懂这是在建设 KB，不是普通问答 |
| AI 回答要硬塞模板吗 | ❌ 不要 | 要自然语言、连贯，但内容结构符合范本 |
| 用户能改气泡内容吗 | ✅ 能 | 「添加到对话」后自由修改，限定条件用户自己加 |
| import_mode 暴露给用户吗 | ❌ 不暴露 | 透明处理，用户不知道有这个概念 |
| 汇入粒度 | AI 整段回答作为资料源 → AI 自动拆分实体 | 和手动粘贴文本进去完全一样，复用 handleWikiIngestAll |
| import_mode 时联网开关 | 强制 ON | 用户点气泡 = 他查 KB 里没有的，必须联网 |
| 气泡里的实体名 | AI 动态推荐 + 和已有页面不重复 | 避免推荐用户已经有的 |

### 8.6 改动范围预估

| 层 | 改动 | 量 | 复用现有逻辑 |
|---|---|---|---|
| Worker | `handleWikiAsk` 加 `import_mode` 分支 | ~30 行 | ✅ 复用 callLLM / wiki_kb_categories 查询 |
| Worker | 新增 `GET /api/wiki/kbs/:kb_id/suggest`（气泡用的实体推荐）| ~20 行 | ✅ 调一次小模型 |
| 前端 AiChatView | 知识 tab 里，特定时机渲染小气泡 | ~50 行 | 新 UI |
| 前端 AiChatView | 发请求时带 `import_mode` + 回答后显示「📥 汇入」按钮 | ~30 行 | ✅ 复用 handleWikiIngestAll |
| | **总计** | **~130 行** | |

### 8.7 气泡触发时机判定代码（前端伪代码）

```javascript
function shouldImportMode(question, kb, context) {
  const firstDialog = !history || history.length === 0;
  const kbEmpty = kb.pageCount === 0;
  const collectingIntent = 
    /收集|查询|整理|帮我找|帮我查|帮我搜/.test(question) 
    && /信息|资料|内容/.test(question);
  const lastAiSaysEmpty = lastAiAnswer?.includes?.("还是空的");
  const lastAiSaysNotFound = lastAiAnswer?.includes?.("暂时没有");

  return firstDialog || collectingIntent || lastAiSaysEmpty || lastAiSaysNotFound;
}
```
