## 二、🔴 三处需要修正

### 修正 1（最重要）：阈值不能照抄文档的0.03 / 0.08

**这是本次评审最需要提醒的一点。**

文档第四节给出：
> 相关问题 bestScore ≥ 0.08 / 无关问题 ≤ 0.02 / 阈值 0.03–0.04 是安全区

**但代码里知识库问答和日记问答用的是两套不同的打分方式**：

| 位置 | 函数 | 关键词分处理 |
|---|---|---|
| `index.js:1798` | `handleAsk`（日记问答） | `kwNorm = kwRaw * maxVec` ← **有归一化** |
| `index.js:2087` | `handleWikiAsk`（**知识库问答**） | `score = 0.7*vecRaw + 0.3*kwRaw` ← **直接用原始分** |

**后果**：两边的**分数分布完全不同**。日记问答做了归一化（分数偏高），知识库问答没有（分数偏低）。

**结论**：
- 如果那个"0.08 = 相关"是**实测知识库问答**得到的 → 可用
- 如果是**参考日记那边的经验** → 偏低，会误杀

**建议**：**阈值必须在 `handleWikiAsk` 里实测取分布，不要用文档给的数字。**

具体做法：Dev 环境先打 20–30 条日志（相关的 + 无关的各一半），看真实分布再定。

---

### 修正 2：reranker 的置信度被误判了

**文档第五节写**：
> 「目前 reranker 只返回排序结果不返回置信度分数」

**核实结果：不准确。** `workers/src/index.js:1816` 明确写着：

```js
// reranker 返回 [{id: 0, score: 0.59}, ...] 按 score 降序排列
```

**reranker 是返回 score 的**，而且它比向量相似度**可靠得多**——它是专门训练的交叉编码器，判断的是"这段文字是否真的回答了这个 query"。

**建议：优先用 reranker 的分数做阈值判断，而不是混合检索的 score。**

理由：

| 信号 | 性质 | 可靠性 |
|---|---|---|
| 混合检索 score（0.7向量+0.3关键词） | 粗筛 | 天花板低 |
| **reranker score（bge-reranker）** | **精排** | **能真正判断相关性** |

而且 **reranker 本来就在跑**（`if (reranked.length >= 3) finalTop = reranked`），只是阈值判断没用它。**低成本高收益的改进。**

### 修正 3：中间区间可再加一道保险（优化项，非必须）

**方案 A 的风险**：阈值定高了会**误杀**。

**更稳的做法**（可补充进方案 C）：

```
分数 ≥ 0.08        → 正常调 LLM
分数 < 0.03        → 直接说"没有"
中间区间           → 调 LLM，明确告知"候选可能都无关"
                      且让 LLM 先输出结构化判断（是/否），再回答问题
```

**关键是让 LLM 先答"是/否"**，而不是自由发挥——即使它想编，也得先跨过这一关。

属于优化项，不是必须。

## 三、🟡 建议把验证前置（阈值调参没数据就是猜）

文档第五节把验证放在"后续优化"，**建议前置**，因为方案 C 的核心就是两个魔法数字。

**必须验证的 4 类 case**：

| 类型 | 例子 | 期望 |备注 |
|---|---|---|---|
| **完全无关** | 知识库是菜谱，问"三体讲了什么" | 拒绝回答 | 文档已覆盖 |
| **同义/换词** | 知识库有"番茄炒蛋"，问"西红柿炒鸡蛋" | **必须能答** | ⚠️ **最容易误杀** |
| **跨页综合** | "肖申克的救赎和百年孤独有什么共同点" | 能答（需多页） | 文档已提及 |
| **实体别名** | 知识库有"迈克"，问"Michael" | **必须能答** | ⚠️ **考验 embedding** |

**第 2、4 类最容易误杀**，文档提到了边界但没细说。建议**每类先测 5 条**，再定阈值。

## 五、优先级与排期

**同意 P0** —— 幻觉直接损害知识库可信度。用户一旦发现"它会瞎编"，就再也不敢用了。

**但执行顺序建议**：

```

```
