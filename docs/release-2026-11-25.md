## 一、改了什么（用户视角）

### 1. 导航改版
- 底栏改成：**今天 · 回忆 · 🎙️ · 小麦 · 我的**
- **今天**（新首页 `/`）：写日记入口、今天的日记、**小麦对每篇日记的回应**、今天解锁的胶囊、今天的计划、30 天内的纪念日、那年今日。没内容的卡片不显示
- **回忆**：顶部切换 `🕰️ 时间线 · 📅 月历 · 👤 人物 · 📚 书柜`；月历从首页移到 `/calendar`
- **小麦**：升为一级入口 `/xiaomai`，首页里原来的「💬 小麦」Tab 去掉
- 新手引导搬到「今天」页，步骤更新

### 2. 知识库 → 「我的生活」
- 每个用户自动有一个「🌾 我的生活」知识库（人物 / 地点 / 事件），日记固定进这里
- 日记修改会同步，永久删除会连带清理
- **每小时自动整理**，不用手动点「汇入」
- 汇入结果如实显示失败份数；隐藏内部"暂停"的预设；去掉返回给前端的调试字段

### 3. 人物页
- 回忆 → 👤 人物：小麦认识的人、去过的地方、发生过的事，按出现次数排序
- 详情：小麦的印象、相关的人和地点、提到 TA 的日记（点开就是原文）
- 可以 **改名 / 合并 / 删除**

### 4. 小麦检索的重要修复
- 日记正文**从来没有进过检索**（只取了标题），已修复
- 新增全量重建向量的管理接口和脚本，部署后要跑一次

## 三、提交建议

四批改动在 `index.js`、`api.ts`、`App.tsx` 等文件里**交叉在一起**，按功能拆 commit 需要逐段 `git add -p`，容易出错。建议**按部署对象拆成 3 个提交**：

```
cd "D:\mydiary code\my-diary"
git status

# 1. 后端（需要 wrangler deploy）
git add workers/
git commit -m "feat(worker): 我的生活知识库+自动整理、人物页接口、小麦回应、修复检索只取标题"

# 2. 前端（push 到 main 后 Pages 自动部署）
git add src/
git commit -m "feat(web): 导航改版（今天/回忆/小麦）、人物页、今天页"

# 3. 文档
git add docs/
git commit -m "docs: 信息架构方案、测试说明、发布说明"
```

> ⚠️ 按 AGENTS.md 约定：commit / push 由翔哥拍板。**push 到 main = 前端直接上线**，务必先走完下面第四节的测试环境验证。

## 五、已知风险与需要观察的

| 项 | 说明 | 怎么处理 |
|---|---|---|
| 定时任务在 dev 不生效 | `[triggers]` 是顶层配置，`[env.dev]` 可能不继承 | 在 `wrangler.toml` 的 `[env.dev]` 下加 `[env.dev.triggers]` + 同样的 `crons` |
| AI 成本 | 每小时自动整理（≤5 用户 × 6 份）+ 每篇日记一次小麦回应 | 调 `wiki.js` 的 `AUTO_INGEST_USERS` / `AUTO_INGEST_SOURCES` |
| 检索阈值 | 正文进入检索后，相似度分布会变 | 重建后开 `DEBUG_ASK` 校准 `RERANK_MIN_SCORE` / `VECTOR_MIN_SCORE` / `REPLY_PAST_MIN_SCORE` |
| 重建向量耗时 | 每篇日记调一次 embedding | 脚本分批 40 篇，失败自动重试；大量日记时可调 `-Limit` |
| prod / dev 范本不一致 | DEPLOY.md 记录过 prod 官方范本比 dev 少 | 「我的生活」缺范本时会用内置格式，不会建库失败 |
| 人物识别准确度 | 谁是谁、归哪类由 AI 判断 | 靠改名 / 合并 / 删除让用户纠正；观察合并使用频率 |
| 老用户的「我的生活」 | 首次创建只回填最近 30 篇 | 更早的日记要等再次保存才会进入；如需全量回填可另写任务 |
